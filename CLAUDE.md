# Aurora Gallery — контекст проекта

Этот файл — память проекта. Claude Code читает его автоматически при открытии папки.
Здесь зафиксировано всё, о чём договорились в режиме Cowork, чтобы продолжить без потерь.

## Видение

Своя галерея, потому что все существующие Михаилу не нравятся: «уродливые,
одинаковые, тормозят». Нужна **красивая, стильная, уникальная, плотная и
очень быстрая** галерея.

Дизайн-направление «Aurora»:
- Тёплая палитра в духе приложения Claude (песочный фон, глиняно-коралловый
  акцент). НЕ «эппловские стекляшки», НЕ старый Material Design.
- Объём за счёт мягких теней и приподнятых поверхностей — не плоско.
- Слегка скруглённые углы.
- Максимум места под картинки, минимум интерфейса (edge-to-edge).
- Настраиваемые цветовые **темы** (сейчас 5: Sand, Charcoal, Forest, Ocean, Plum;
  переключаются точками в шапке). Темы заданы в `lib/theme.dart` —
  добавить тему = добавить один объект `AuroraColors`.

## Технологии и почему

- **Flutter** (Dart). Причина: один код под Android, Windows, Linux; отличный
  контроль над внешним видом (нужен для уникального дизайна); хорошая
  производительность; подходит планшету. На Apple НЕ ориентируемся.
- Порядок платформ по договорённости: **сначала Windows** (можно сразу
  запускать и проверять на ПК), потом Android, потом Linux.

## Как собирается приложение (важно)

Локально Flutter у Михаила пока НЕ установлен. Сборка идёт **в облаке через
GitHub Actions**, чтобы ему не ставить тяжёлый тулчейн.

- Репозиторий на GitHub (приватный). Workflow: `.github/workflows/build.yml`
  собирает Windows-приложение на `windows-latest` и выкладывает артефакт
  `aurora-gallery-windows` (zip с `aurora_gallery.exe` + файлы рядом).
- Платформенные папки (`windows/`, `android/`) в репозиторий НЕ кладём — workflow
  генерирует их на лету через `flutter create --platforms=...`. Поэтому они в
  `.gitignore`.
- Текущий статус: Windows-сборка собирается и **успешно запускается на ПК
  Михаила**. Проверена версия с UI-каркасом; версия с чтением реальных файлов
  залита/заливается следующей.

### Что улучшить в Claude Code (снимает ручную возню)

В Claude Code команды выполняются на машине Михаила, поэтому можно:
1. Поставить `git` (и при желании Flutter) командами, настроить аутентификацию.
2. Вести проект через git: `git init`, коммиты, `git push` — без ручной
   загрузки файлов на сайт GitHub.
3. Следить за сборкой и качать артефакты через `gh` CLI
   (`gh run watch`, `gh run download`).
4. Опционально — установить Flutter локально и собирать/запускать на ПК напрямую,
   а не только через облако.

## Архитектура и карта файлов

```
lib/
  main.dart            — запуск, состояние активной темы (AuroraTheme InheritedWidget)
  theme.dart           — палитры тем (AuroraColors) + сборка ThemeData
  model.dart           — PhotoItem, AlbumItem, помощники (даты, размер, группы)
  library_service.dart — сканирование папок с диска, группировка в альбомы,
                         запоминание выбранной папки (shared_preferences)
  home_page.dart       — главный экран: боковая панель, шапка, режимы (Все/По датам/
                         Альбомы), регулятор плотности, сетки, экран папки
  viewer_page.dart     — полноэкранный просмотрщик (свайпы, зум, инфопанель)
  sample_data.dart     — НЕ используется (остаток от демо на тестовых картинках)
.github/workflows/build.yml — облачная сборка под Windows
```

Зависимости (`pubspec.yaml`): `file_picker` (выбор папки), `shared_preferences`
(запоминание папки), `cupertino_icons`.

### Что уже работает

- Выбор папки на диске → рекурсивное сканирование изображений
  (jpg/jpeg/png/gif/webp/bmp/jfif).
- Режим «Все» — плотная сетка; «По датам» — группировка по дате изменения файла;
  «Альбомы» — папки с обложками и счётчиками, клик открывает содержимое папки.
- Регулятор плотности (размер плиток меняется вживую).
- Просмотрщик: реальные имя/размер/путь/дата, свайпы между фото, зум.
- Выбранная папка запоминается между запусками.
- 5 переключаемых тем.

## Принципы производительности (критично — не нарушать)

Цель: не тормозить НИКОГДА, даже на 100к+ изображений. Те галереи, что
«мгновенно показывают всё», держат на экране лишь видимое и не декодируют
полные файлы в сетке. Правила:

1. **Виртуализация**: сетки только на `GridView.builder` / `SliverGrid` —
   строятся лишь видимые плитки.
2. **Уменьшённые миниатюры**: в сетке `ResizeImage(FileImage(...), width: cacheWidth)`,
   где `cacheWidth ≈ размер_плитки × devicePixelRatio`. НЕ декодировать полное
   изображение в сетке. Полный размер — только в просмотрщике.
3. **Фоновая работа**: сейчас скан идёт в основном потоке со спиннером —
   СЛЕДУЮЩЕЕ улучшение: вынести скан в `Isolate` (через `compute`), чтобы UI не
   подмерзал на больших папках.

## План авто-тегирования (ключевая фича для Михаила)

Нужны теги в стиле danbooru/e621, локально (без интернета, ничего не уходит),
по кнопке «запустить тегирование». Контент разнородный: фурри-арт, аниме,
реалистичные фото людей, природа, скриншоты, документы, реалистичный NSFW.
Единой модели на всё нет — делаем **конвейер** локальных ONNX-моделей:

1. **Роутер типа** (CLIP/SigLIP, zero-shot): определяет тип картинки словами,
   задаваемыми нами (рисунок / реалистичное фото / скриншот / документ / природа /
   люди). Вешает тег типа и направляет в нужный таггер.
2. **RAM++ (Recognize Anything)** — для реальных фото: 6400+ обычных категорий
   (люди, природа, предметы, сцены).
3. **JoyTag / WD-v1.4 / e621-таггеры** — для рисованного арта (danbooru/e621-теги).
   JoyTag хорош для furry/NSFW. e621-словарь — отдельной моделью при необходимости.
4. **NSFW-классификатор** — единый флаг safe/questionable/explicit, работает и на
   рисунках, и на реальных фото.

Запуск через ONNX Runtime (есть сборки под Android/Windows/Linux). Тегирование —
останавливаемая/возобновляемая фоновая задача с прогрессом; результаты в
локальную БД и кэшируются навсегда; порог уверенности настраивается; теги можно
править вручную. Суммарно модели ~1–2 ГБ на устройстве (скачать один раз).

## Дорожная карта

1. ✅ UI-каркас + сборка под Windows.
2. ✅ Чтение реальных фото/папок с диска + уменьшённые миниатюры.
3. Скан в Isolate + кэш миниатюр на диск (мгновенный повторный запуск).
4. Быстрый поиск, избранное, реальные действия (удалить/поделиться/в альбом).
5. Сборка под Android (тот же код, отдельный workflow) + доступ к фото устройства
   (пакет `photo_manager`, разрешения).
6. Авто-тегирование: конвейер ONNX-моделей (см. выше).
7. Сборка под Linux.
8. Авто-обновление из GitHub Releases (для Windows — через помощник-обновлятор
   или MSIX, т.к. запущенный .exe не перезаписывает себя на лету).

## Как продолжить в Claude Code (первые шаги)

1. Открыть эту папку проекта в Claude Code (запустить `claude` в каталоге
   `aurora_gallery`). Этот файл подхватится автоматически.
2. Проверить наличие git: если нет — поставить. Настроить доступ к GitHub
   (репозиторий уже существует у Михаила; узнать его URL или создать через
   `gh repo create`).
3. Связать локальную папку с репозиторием, сделать первый коммит/пуш — дальше
   все правки идут через git, без ручной загрузки на сайт.
4. Дождаться зелёной сборки (`gh run watch`), скачать артефакт, проверить на ПК.
5. Продолжать по дорожной карте — следующий приоритет: пункт 3 (Isolate + кэш
   миниатюр), затем авто-тегирование.
